ibernate 7.4: Delegating UUID Generation to PostgreSQL
📝 The Issue

When using PostgreSQL's DEFAULT gen_random_uuid() for primary keys, Hibernate can generate UUIDs in the application instead of letting PostgreSQL generate them, depending on how the entity is mapped.

If Hibernate generates the UUID, the generated SQL looks like:

insert into organizations (..., id)
values (..., ?)

Because the id column is explicitly included, PostgreSQL never gets a chance to apply its DEFAULT gen_random_uuid() value.

If the goal is for PostgreSQL to be the single source of truth for ID generation, Hibernate must be configured to treat the value as database-generated.

✅ The Correct Configuration

To delegate UUID generation to PostgreSQL, use Hibernate's @Generated annotation together with a database default.

import jakarta.persistence.Entity;
import jakarta.persistence.Id;
import jakarta.persistence.Table;

import org.hibernate.annotations.ColumnDefault;
import org.hibernate.annotations.Generated;

@Entity
@Table(name = "organizations")
public class Organization {

    @Id
    @Generated
    @ColumnDefault("gen_random_uuid()")
    private UUID id;

    // ...

}

Database column:

id UUID PRIMARY KEY DEFAULT gen_random_uuid()
⚠️ Annotation Differences
@GeneratedValue
@Id
@GeneratedValue
private UUID id;

This tells Hibernate to generate the identifier according to its configured identifier strategy.

For UUID identifiers, modern Hibernate commonly generates the UUID in Java before executing the INSERT.

Result:

insert into organizations (..., id)
values (..., ?)
jakarta.annotation.Generated
import jakarta.annotation.Generated;

This annotation has nothing to do with persistence.

It is simply metadata indicating code generation and should not be used for entity ID generation.

org.hibernate.annotations.Generated
import org.hibernate.annotations.Generated;

This tells Hibernate that the value is generated by the database.

Combined with a database default, Hibernate:

omits the column from the INSERT
allows PostgreSQL to generate the UUID
retrieves the generated value using PostgreSQL's RETURNING support

Result:

insert into organizations
(created_at, name, slug, updated_at)
values (?, ?, ?, ?)
returning id
💡 Why This Works

There are two independent concerns:

Who generates the UUID?
How does Hibernate obtain the generated value?

Using:

@Generated
@ColumnDefault("gen_random_uuid()")

tells Hibernate:

"The database will provide this value."

Hibernate therefore:

excludes the column from the INSERT
lets PostgreSQL evaluate the DEFAULT expression
fetches the generated value afterward

This keeps PostgreSQL as the single source of truth for identifier generation.
